# 1.1 The agentic loop (Domain 1, 27% of the exam)

Code: `study/day1/agent.py` (the loop) and `study/day1/inspect_loop.py` (prints the conversation after every call).

## Words
- **Model**: the AI (Claude). **API**: how your code talks to it over the internet. **JSON**: plain-text structured data.
- **Tool**: a normal function in your code that Claude can ask you to run. **Agent**: a model that uses tools over several steps.

## Why tools
A model alone can only write text. It cannot act, cannot see your data, and may guess facts. Tools let it ask; your code does the work. Claude never runs your code.

## Three parts of a tool
1. **Definition**: name, plain-English description, inputs. Claude reads the description to choose the tool.
2. **Request**: Claude's `tool_use` block (name, inputs, unique id).
3. **Function**: the real Python code that returns a result.

## The conversation is a list you resend
The API remembers nothing between calls. Each call sends the whole `messages` list. Roles: `user` and `assistant`. Claude's reply is a list of blocks: `text` and `tool_use`. You answer with a `tool_result` block carrying the same id, inside a `user` message. If Claude asks for several tools at once, return all the results together.

## stop_reason
| Value | Meaning | Do |
|---|---|---|
| `tool_use` | Wants a tool run | Run it, append reply and result, call again |
| `end_turn` | Finished | Stop, show the answer |
| `max_tokens` | Cut off by the length limit, not finished | Treat as an error |

## Loop
Send question and tools. Read `stop_reason`. `tool_use`: run tools, append, repeat. `end_turn`: done. Anything else: fail loudly. Claude decides which tools and in what order (model-driven). Your code only follows `stop_reason`.

## Exam traps (wrong ways to stop)
- Reading the text for "done". Wording varies, and text can arrive with a tool request.
- An iteration cap as the *main* stopper. Fine as an extra safety limit only.
- Checking whether the reply has text.

Right answer: `stop_reason`.

## Problem solved
Weaves questions often need lookups where the second depends on the first ("which weaves from West Bengal, and what do they cost?"). One call cannot do that, and a fixed script cannot cover every question.

## What the experiments showed
- A: "What is 2 + 2?" took 1 call, `end_turn`. Having tools does not force their use.
- B: West Bengal question took 3 calls and 2 tool runs. The list grew each call, ids matched, and Claude chose the price tool because of the first result.
- C: `max_tokens=5` gave `max_tokens` and an empty answer. This is why `agent.py` raises an error on unexpected values.
