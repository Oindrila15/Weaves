## Ask or force
- **Ask** (prompt): Claude follows it by judgement. A probability. Like a "Staff only" sign.
- **Force** (code): your program follows it every time. A guarantee. Like a locked door.
- Costly if broken (privacy, money, consent, safety): enforce in code. Preference (tone, format): a prompt is fine.
- Exam pattern: programmatic enforcement beats a stronger prompt when a rule must always hold.

## 1.4 Enforcement and handoffs
- **Prerequisite gate**: block a step until an earlier step succeeded (verify identity before a refund; check consent before showing contact).
- **Handoff to a human**: the human cannot see the chat, so send a structured summary (who, problem, what was tried, recommended action). For Weaves: "Know a weaver?" submissions need source, claims and trust level.

## 1.5 Hooks
A hook is a function the loop calls at a fixed point.
- **PreToolUse**: runs before the tool. Can allow, block, or change inputs. A block returns a tool result flagged `is_error` with the reason and what to do instead.
- **PostToolUse**: runs after the tool, before Claude sees the result. Cleans, trims or normalises it.
- Built into Claude Code and the Agent SDK. In the raw API loop we call the functions ourselves; the idea is the same.
- Traps: a block with no explanation makes Claude retry the same call. A hook must decide from real inputs and data, never from Claude's wording.

## What the run showed
- Without the hook, weaver `w2` (no consent) had their phone number handed out.
- With the pre hook, the call was blocked, Claude told the user it cannot share it and offered other information.
- `w1` (consent given) passed through untouched.
- The post hook turned `[8000, 100000]` into `INR 8,000 to 100,000` before Claude saw it.
- In the price run, the first tool call used a wrong weave name (`Banarasi saree`), got an error, and Claude retried with `Banarasi`. The loop lets Claude recover from a tool error.

## My weak spots
- A human handoff needs a structured summary because the human receives only the handoff, not the conversation. The summary (who, problem, what was tried, recommended action) saves them from asking the customer everything again. It is not about the Python script and Claude talking to each other.
- A prompt rule can also fail because Claude lacks the data to apply it (the tool result had no consent field). In the experiment it leaked on a plain request and held only when the user mentioned consent.
