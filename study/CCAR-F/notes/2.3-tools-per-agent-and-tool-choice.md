# 2.3 Tools per agent and tool_choice (Domain 2, 18% of the exam)

Code: `study/CCAR-F/day2/tool_counts.py`. Also CCA-P 3.1 (capability bloat) and groundwork for 3.2 (authorisation, least privilege).

## Rules to remember
- **4 to 5 focused tools per agent** beat 18. Give each agent only the tools its role needs.
- Capability bloat costs three things: **tokens and time** (every tool definition is sent on every request), **choice errors** (more look-alikes), and **risk** (every tool is something that can be misused).
- **Least privilege**: remove what the role does not need. Removing is preventive; logging and confirmation prompts are detective or compensating. Removing wins.
- Ways to cut the count: split into specialised agents, merge near-duplicates, load tools on demand.

## tool_choice
| Setting | Meaning | Use when |
|---|---|---|
| `auto` (default) | Claude may answer in text or call a tool | Normal chat and agent loops |
| `any` | Claude must call a tool, its choice | You need a tool call, not prose (for example structured output) |
| `{"type": "tool", "name": "X"}` | Claude must call tool X | A step must come first (extract metadata, then continue) |

Trap: forcing a tool makes Claude invent inputs if the question does not fit it. Do not force on every call.

## What the experiment showed (Haiku)
| Setup | Accuracy (30 runs) | Input size per request |
|---|---|---|
| 4 tools | 30/30 | about 734 tokens |
| 18 tools, all genuinely different jobs | 30/30 | about 1,974 tokens (2.7 times more) |

- Accuracy did NOT drop on this model, because the 14 extra tools were distinct. The cost was tokens. Real bloat usually adds look-alikes, which is where errors appear.
- `auto` on a greeting: plain text, `end_turn`. `any`: still called a tool (`list_weaves_by_region('India')`) for a greeting. Forced `get_weave_price` on a greeting: invented the input `'jamdani'`.
- Forced `get_weave_price` on a region question: called it with `'Tamil Nadu'` as a weave name (wrong input), plus a second call.
- A role without `get_weaver_contact` could not leak a number: it said it had no tool for that. No hook needed for that path.

## My weak spots
- **`publish_fact` belongs to no agent.** I removed it in check question 3 but gave it to two agents in the tool lists. Same principle both times: facts go live only after human review. The discovery agent also reads untrusted web pages, which is the main route for prompt injection, so it is the last agent that should publish.
- An agent needs a way to **read** what it works on. The knowledge builder had no fetch or search tool.
- `tool_choice`: **`any`** = must call some tool (pipeline result must be a tool call). **Forced** = a specific tool must come first (verify identity). Forced is only right when exactly one tool is meant.
- What forcing a tool does wrong: Claude must call a tool that does not fit the question, so it fills in wrong or made-up inputs (it passed 'Tamil Nadu' as a weave name). Say "forced call with a wrong input", not just "hallucination".
